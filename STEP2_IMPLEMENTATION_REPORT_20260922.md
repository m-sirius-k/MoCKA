### 2. gateway/adapter_gpt.py (MODIFIED - 12 new lines)

**Location:** handle_function_call() method (lines 99-117)

**Change:** Added HABBridge call in parallel with existing /api/v1/event path (backward compatible)

**New Code:**
```python
# STEP 2: Try HAB Bridge if available
if HAB_BRIDGE_AVAILABLE:
    try:
        bridge = HABBridge()
        hab_context = {
            "decision_id": None,  # Let bridge generate
            "scope": tags or ["default"],
            "authority_role": "AI_AUTHORITY",
            "note": description,
        }
        bridge_result = bridge.submit_from_ai(f"{model}_{runtime}", hab_context)
        if bridge_result.get("status") == "ok":
            result["hab_request_id"] = bridge_result.get("request_id")
            result["hab_state"] = bridge_result.get("state")
            result["hab_decision_id"] = bridge_result.get("decision_id")
    except Exception as hab_err:
        result["hab_error"] = str(hab_err)
```

**Behavior:**
- Gracefully degrades if HAB not available (HAB_BRIDGE_AVAILABLE flag)
- Keeps existing /api/v1/event POST for backward compatibility
- Returns both MoCKA event_id AND HAB request_id/decision_id

## Authority Boundaries - VERIFIED

**Fail-Closed Guarantees Maintained:**

1. [X] Bridge does NOT auto-approve
   - HAB.submit() creates PENDING state only
   - External approval required by Human Authority

2. [X] Bridge does NOT route to JARVIS
   - No implicit JARVIS.receive_decision_from_hab() call
   - External routing required

3. [X] Bridge does NOT execute T2
   - No T2 Runtime calls
   - Execution only after full authorization chain

4. [X] No new Authorization creation
   - Bridge normalizes existing context only
   - Authorization State generated by approve(), not Bridge
