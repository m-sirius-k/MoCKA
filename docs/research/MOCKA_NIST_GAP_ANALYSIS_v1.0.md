# MoCKA × NIST Gap Analysis v1.0

**Input (canonical):** `MOCKA_NIST_REQUIREMENT_MAPPING_v1.0.md`. This document extracts every **NONE** and **PARTIAL** row from that mapping (14 NONE + 33 PARTIAL = 47 of 53 Tasks; corrected during the Task7/8 audit pass from an earlier "49 of 54" mis-tally — see the Mapping document's Summary Tally correction note) and, per R01 instruction, carries each through: **NIST要求 → MoCKA現状 → 不足理由 → 改善案 → 優先順位**. No new NIST requirements are introduced; no new MoCKA research was performed to produce this document — it restructures findings already recorded in the Mapping document. Note: several rows below deliberately combine closely related Task IDs (e.g., "3.2 / 4.5") into a single narrative entry where they share one root cause, so the row count in the tables is lower than 47 even though all 47 Task-level gaps are covered.

**Priority scale:** **高 (High)** = an currently-open, evidenced institutional risk (appears in the Integrity Ledger as `status: Open`) or a direct contradiction between stated policy and actual code behavior. **中 (Medium)** = a real capability gap whose absence would matter if MoCKA's scope expanded, but is not currently causing a live incident. **低 (Low)** = gap exists primarily because of the domain-scope mismatch (MoCKA is not a CI/OT operator) — closing it would require MoCKA to acquire a mission it does not have, so the realistic 改善案 is *explicit scoping documentation*, not new engineering.

## Category A — Gaps that are domain-scope mismatches (MoCKA is not a CI/OT operator)

Of the 16 rows below, 13 are true NONE-status domain-scope mismatches (2.1, 2.5, 3.6, 4.3, 6.1, 6.3, 8.4, 8.5, 9.1, 9.3, 11.1, 11.3, 11.5). The remaining 3 rows (5.1, 3.5, 1.4) are PARTIAL-status items included here because their 改善案 is the same "low-cost, non-engineering" character as the domain-mismatch items, not because they are themselves domain mismatches — each row below states its actual reason individually rather than assuming the category header applies uniformly.

These 16 NONE items share one root cause and one honest remediation: MoCKA is a software/knowledge-governance system, not an operator of physical critical-infrastructure assets. Listing them individually per R01 instruction, but grouping the 不足理由/改善案 narrative since it repeats.

## Consolidated Priority View

**高 (High) — currently open, evidenced institutional risk, recommend addressing first:**
1. Human Gate enforcement gap on `/audit/seal` execution path (IC_20260708_004) — affects Tasks 3.2, 4.1, 4.5, 7.4
2. Missing authentication middleware in `app.py` — affects Tasks 5.2, 5.3
3. COMMAND CENTER seal-status display pointing at a defunct file (IC_20260707_005) — affects Tasks 4.2, 10.2

Note that items 1 and 3 are each already known to MoCKA's own governance process (referenced as TODO_429-boundary and TODO_371 respectively in project records) — this Gap Analysis is not surfacing them for the first time, but confirming, via independent NIST-framework mapping, that they land on genuinely high-value NIST-relevant control points, which is itself useful triangulation.

**中 (Medium) — 12 items**, mostly: formalize what already exists informally (champion-challenger pattern, requirements-baseline tagging, dependency/blast-radius mapping, granular artifact classification), or close verification debt (read the name-only governance docs before citing their status further).

**低 (Low) — 15 items**, almost entirely the Category A domain-scope mismatches, where the correct action is explicit scoping documentation rather than new engineering.
