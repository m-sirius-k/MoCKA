## 1. Motivation

Restating the gap precisely, because the rest of this document is built directly on top of it: Theorem 4 (Decentralized Safety Preservation), as given in `docs/formal/references/pders_main_reference.md`, proves - by induction on trace length, using only node i's own Local Invariant Gate and Lemma 2 (Local Invariant Preservation) - that node i's own accepted trace stays safe and stays observation-equivalent to *some* global specification trace. It is quantified over a single node i. It says nothing, and its proof uses nothing, about a second node j. Assumption 4 (Projection Consistency - `Ωi = Ωj`, `Ψi = Ψj` on the shared projection `S^ij`) is listed among Theorem 4's stated hypotheses but plays no visible role in discharging its conclusion.

What the paper's own narrative gestures at, without stating as a numbered theorem, is a stronger, genuinely multi-node claim: that safety established independently and separately by every node composes into one coherent global safety guarantee (Figure 1's "Cryptographic composition... -> global safety proof", Corollary 5's framing of "the accepted execution history" as if it were one shared object rather than n separate per-node histories). This document's task is to actually attempt that theorem - not the paper's, since the paper does not state it, but a new one, built on the paper's own definitions - and to be honest about exactly how far the attempt gets.

Two branches inherited from `pDERS_overlap_consistency_v0.2.md` Section 3 structure everything below:

- **Branch 1**: `Ωi`/`Ψi` are all derived, in some disciplined way, from a single shared design-time policy.
- **Branch 2**: `Ωi`/`Ψi` are independently authored per node, with no shared reference.

Section 2 attempts a real Compositional Safety Theorem under Branch 1 and shows exactly where the attempt stops. Section 3 does not attempt a Branch 2 theorem (v0.2 already showed this is not derivable from the paper's own material) but instead formally identifies what additional mechanism would be needed, and evaluates candidates against C1/C2.

## 2. Branch 1: Compositional Safety Theorem under Shared-Policy Derivation

### 2.1 A precise version of the Branch 1 discipline

`pDERS_overlap_consistency_v0.2.md` Section 3.2 described Branch 1 informally, as `Omega_i(s) := GlobalPolicy(lift_i(s))` for "some consistent lifting." Making this precise turns out to require two separate conditions, not one - this is itself a small but genuine sharpening of v0.2's account, developed here because the compositional theorem needs both explicitly.

**Condition F (Factorization).** There exists a single `Omega_G : Sspec -> {0,1}` (and similarly `Psi_G` over `Sspec x L x Sspec`) such that for every `i in N`: whenever `sigma, sigma' in Sspec` and `pi_i(sigma) = pi_i(sigma')`, then `Omega_G(sigma) = Omega_G(sigma')`. (I.e. `Omega_G` does not distinguish global states that node i's own projection collapses together - it "factors through" `pi_i`.) Given F, `Omega_i(s) := Omega_G(sigma)` for any `sigma` with `pi_i(sigma) = s` is well-defined for each `i` separately.

**Condition C (Coherent Overlap).** For every `i, j in N` and every `s in S^ij = pi_i(Sspec) intersect pi_j(Sspec)`, there exists a *single* `sigma in Sspec` with `pi_i(sigma) = pi_j(sigma) = s`.

Condition C is not implied by Condition F, and neither is stated among Assumptions 1-4 in the paper as transcribed. The reason both are needed, separately, is worked out in Lemma A below - this is genuinely new content relative to v0.2, which treated "derived from one shared policy" as a single informal condition.

### 2.2 Lemma A (Overlap State Agreement) - proven

**Lemma A.** Given Condition F and Condition C, Assumption 4 (`Omega_i = Omega_j`, `Psi_i = Psi_j` on `S^ij`, for every `i, j in N`) holds.

*Proof.* Fix `i, j in N` and `s in S^ij`. By Condition C, there is a single `sigma in Sspec` with `pi_i(sigma) = pi_j(sigma) = s`. By Condition F applied to node i, `Omega_i(s) = Omega_G(sigma)` (well-defined, using this specific `sigma` as the witness). By Condition F applied to node j, `Omega_j(s) = Omega_G(sigma)` (the *same* `sigma`, since Condition C guarantees a single common witness, not merely one witness for each node separately). Hence `Omega_i(s) = Omega_G(sigma) = Omega_j(s)`. The identical argument, with `Psi_G` and pairs `(s,l,s')`, gives `Psi_i = Psi_j` on `S^ij`. []

Why Condition F alone is not enough (the point of separating F from C): Condition F, applied to node i and to node j *separately*, only guarantees `Omega_i(s) = Omega_G(sigma_i)` for *some* `sigma_i` with `pi_i(sigma_i)=s`, and `Omega_j(s) = Omega_G(sigma_j)` for *some*, possibly different, `sigma_j` with `pi_j(sigma_j)=s`. Membership of `s` in the set-intersection `S^ij` only says both preimages are individually nonempty - it does not say they can be taken to be the *same* global state. Without Condition C, `Omega_i(s)` and `Omega_j(s)` could be `Omega_G` evaluated at two genuinely different global states that both happen to project to the same local observation `s`, and Condition F gives no reason for `Omega_G` to agree on those two different states. This is a real gap in the informal "derived from one shared policy" account, not a pedantic technicality: it means Branch 1, as v0.2 described it, was implicitly assuming something (Condition C) beyond what it stated, and this document is making that assumption explicit rather than continuing to leave it folded invisibly into "derived from a shared policy."

Condition C is a substantive assumption about the family `{pi_i}` as a whole - informally, it says the projections are "coordinate-like" (an overlap observation genuinely corresponds to one shared underlying global state, not to a coincidental collision between two unrelated global states). This is consistent with how `pi_i` was originally described, informally, at the start of this Track A series (`pDERS_causal_projection_v0.1.md` Section 1.1: "a plain coordinate projection"), but it is not among Assumptions 1-4 as transcribed, and this document does not show it follows from them. It is recorded as an open question (Section 5).

### 2.3 Causal Alignment (inherited from v0.1, not re-proven here)

Lemma A gives *pointwise* agreement: wherever node i and node j both observe the same shared global state, their safety verdicts agree. It says nothing about *time* - about whether node i's and node j's traces visit the overlap in a mutually consistent order, which matters because the system is asynchronous (Adversarial Model C2, Causal Reordering) and no global clock is assumed.

This is exactly the content of Lemma 1 (Clock Agreement on Overlap) in `pDERS_overlap_consistency_v0.1.md` Section 3.2, already proven in this Track A series: under Candidate B (vector clocks, `pi_i^causal(s) = (pi_i(s), V_i)`), with a static node index set, two nodes with overlapping causally-relevant event sets cannot disagree about the order or concurrency of events in the overlap, because the vector clock value of an event is a property of the event itself, not of which node reads it.

This document invokes that lemma as-is, under the same caveat it already carries: it holds only for a **static, shared node index set** (`pDERS_overlap_consistency_v0.1.md` Section 3.2's caveat, restated as Open Question 4 there and again in `pDERS_overlap_consistency_v0.2.md` Section 5.2). Call this the **Causal Alignment Hypothesis** for the rest of this document.

### 2.4 The Compositional Safety Theorem - statement

**Theorem (Branch 1 Compositional Safety, attempted).** Let `{i1, ..., im} subset N` be any finite set of nodes with accepted traces `sigma^{i1}_eff, ..., sigma^{im}_eff` (each satisfying Theorem 4's per-node conclusion, which holds by the paper's own Theorem 4, unconditionally on anything in this document). Assume:

1. Assumptions 1-3 (Projection Homomorphism, Monotonic Refinement, Observation Consistency), as in the paper.
2. Condition F and Condition C (Section 2.1) - hence, by Lemma A, Assumption 4 holds for every pair among `{i1,...,im}`.
3. The Causal Alignment Hypothesis (Section 2.3) for `{i1,...,im}`.

Then: there exists a single `sigma_spec in T(delta_spec)` such that for every `k`, `sigma^{ik}_eff ~_{ik} pi_{ik}(sigma_spec)`, and `Omega_G(sigma_spec[t]) = 1` at every point along `sigma_spec` that lies in `pi_{ik}(Sspec)` for some `k` (i.e., safety is guaranteed on the union of what the participating nodes actually observe - this document does not claim anything about the unobserved remainder of `Sspec`, consistent with how Theorem 4 itself only ever speaks about what a node observes).

### 2.5 Proof attempt - what is established and where it stops

**Step 1 (pairwise state and order compatibility) - established.** For any two nodes `ik, il` among the participating set, Lemma A (Section 2.2) gives that wherever their traces' images coincide in `S^{ik,il}`, the safety verdict `Omega_{ik}`/`Omega_{il}` agrees, and the Causal Alignment Hypothesis (Section 2.3) gives that they agree on the causal order/concurrency of any events touching that overlap. Together, these rule out the two failure modes `pDERS_overlap_consistency_v0.1.md`'s own Lemma 2 attempt identified as blocking a bridge argument in that document: a semantic disagreement about whether a shared state is safe (closed here by Lemma A) and an ordering disagreement about shared events (closed by Causal Alignment / v0.1 Lemma 1). This is real, incremental progress relative to both predecessor documents - v0.1 could not close either failure mode (its own Lemma 2 was left unproven precisely because it lacked the paper's actual `Omega_i`/`Psi_i` content); this document closes both, under Branch 1's now-explicit two-part discipline.

**Step 2 (constructing one global trace from pairwise-compatible local traces) - NOT established.** Step 1 shows that any two nodes' local traces are *compatible* wherever they overlap: no contradiction can arise from comparing them. It does not show that a single global element `sigma_spec in T(delta_spec)` actually *exists* that simultaneously realizes every participating node's local trace as its projection. This is a different kind of claim - an existence/lifting claim about the global transition relation `delta_spec`, not a compatibility claim about local observations.

To see precisely why Step 1 does not deliver Step 2: Theorem 4's own single-node existence claim (`exists sigma_spec s.t. sigma^i_eff ~_i pi_i(sigma_spec)`) is licensed, node by node, by the Local Refinement Rule's own phrasing - a transition is admissible *if and only if* a corresponding projected-specification transition exists (`docs/formal/references/pders_main_reference.md`, "Local Refinement Rule"). This is, in effect, built into what "accepted" means for node i alone: acceptance already presupposes a per-node spec-witness. But nothing in that per-node guarantee forces node i's witness and node j's witness to be extendable to *one* global `sigma_spec` covering both. Two individually-consistent local histories can, in principle, correspond to two different, mutually incompatible global runs that happen to agree wherever directly compared (Step 1), while there is no single global run realizing both simultaneously - much as two locally-consistent partial functions need not glue into one consistent total function without an explicit compatibility-and-covering argument (the general shape of this problem is the same one sheaf-gluing conditions exist to solve in other settings; this document does not invoke sheaf theory formally, only notes the shape of the gap for anyone wanting to pursue closing it that way).

**Lemma B (Global Trace Existence / Lifting) - stated, NOT proven.** Under hypotheses 1-3 of the Theorem (Section 2.4), there exists a single `sigma_spec in T(delta_spec)` simultaneously realizing every participating node's accepted trace as its projection.

What would be needed to prove Lemma B, as far as this document can identify: a completeness/surjectivity property of the projection family `{pi_i}` with respect to `delta_spec` - informally, a guarantee that any family of local transitions that are individually valid *and* pairwise compatible on their overlaps (which Step 1 establishes) can always be threaded together into one actual sequence of `delta_spec`-transitions. This is not implied by Assumption 1 (Projection Homomorphism), which is one-directional (a global transition projects down to a locally-consistent one; it says nothing about when a locally-consistent transition lifts up to a global one). It is not implied by Assumptions 2-3 either, nor by Condition F, Condition C, or Causal Alignment as stated - all four of those are about *consistency of observations*, not about *completeness/reconstructability of the global process*. This document does not attempt to supply such a lifting property, does not know whether one is reasonable to assume for a general `{pi_i}` family, and does not know whether Lemma B is in fact false for some `{pi_i}` satisfying everything else in this document's hypotheses (no counterexample was constructed either - this was not attempted, and is listed in Section 5 as unexplored in either direction).

### 2.6 Summary of what is proven and what is not

- **Proven**: Lemma A (Overlap State Agreement), given Conditions F and C - a clean, complete proof (Section 2.2).
- **Proven (inherited, not re-derived)**: Causal Alignment on overlaps, given Candidate B vector clocks and static node membership - this is `pDERS_overlap_consistency_v0.1.md`'s own Lemma 1, carried over as-is with its existing caveat.
- **Established as a consequence of the above two**: pairwise local-trace compatibility (Section 2.5, Step 1) - no contradiction can arise between any two participating nodes' accepted histories, either in safety verdicts or in causal ordering, on their shared observations.
- **NOT proven**: that pairwise compatibility is sufficient for the existence of one single global witness trace realizing all participating nodes simultaneously (Lemma B, Section 2.5, Step 2). This is the precise point where the Compositional Safety Theorem, as stated in Section 2.4, stops being a proof and becomes an open conjecture with a named missing ingredient.

The Branch 1 Compositional Safety Theorem is therefore **not fully proven by this document**. What this document adds beyond v0.1/v0.2 is: a sharper, two-part account of what "Branch 1" actually requires (Condition F is not sufficient alone; Condition C is a separate, additional, previously-unstated requirement); a complete proof that these two conditions together deliver Assumption 4 (Lemma A); and a precise identification of exactly one further gap (Lemma B) as the sole remaining obstacle to the full theorem, rather than an undifferentiated "not sure how to close this."

## 3. Branch 2: What Is Missing

v0.2 already established that Assumption 4 is not derivable from the paper's own material under Branch 2 (independently-authored `Omega_i`/`Psi_i`), and that C1 (Partial Observability) blocks any node from unilaterally verifying it, with the paper's only related architectural component (Async Drift Compensator) being asynchronous and post-acceptance. This section does not re-argue that; it asks the question the instructing memo poses: what, formally, would need to be added to make a Branch-2-style system provably compositionally safe, and how do the candidate additions fare under C1 (and, where relevant, C2)?

Three candidate mechanisms are considered. None is claimed to be practically implementable - per the instructing memo's explicit instruction, this section identifies theoretical necessary/sufficient conditions only, not implementation feasibility.

### 3.1 Candidate (a): a synchronous cross-node verification gate

**Formal shape.** Extend the Local Invariant Gate concept: before a transition touching a shared observation `s in S^ij` is accepted at node i, node i and node j execute a synchronous protocol - node i sends `s` to node j, node j evaluates `Omega_j(s)` locally and returns the boolean, and node i's acceptance additionally requires this returned value to match its own `Omega_i(s)`. Call the resulting gate `Accept_2(s,l,s') := Ri ^ Omega_i(s')=1 ^ Psi_i(s,l,s')=1 ^ CrossCheck(i,j,s')=1`, where `CrossCheck` performs the round-trip described above.

**Sufficiency.** If it can be executed reliably, this mechanism directly discharges exactly what Assumption 4 asks for, at exactly the moment the paper's own Security Objective says it must hold (before state mutation) - it is theoretically sufficient to close the Branch 2 gap identified in v0.2 Section 3.3, without requiring Condition F or Condition C at all (it checks the actual runtime values, not a design-time-derived guarantee).

**Cost under C1/C2.** This mechanism does not violate C1 as literally worded (the system model already permits asynchronous message-passing between nodes; a synchronous request-response exchange is a stronger requirement than that, but not something C1 declares outright impossible). Its real cost is architectural, and severe: it reintroduces, for every transition touching any overlap, precisely the global-synchronization dependency the paper's whole design explicitly sets out to avoid (Abstract: "without requiring globally synchronized state transitions"; the Figure 1 description's own framing: "Global R is uncomputable in async distributed settings - local pi_i projections are sufficient and affordable"). It also introduces a new liveness/availability failure mode not present in the original single-node Gate: what happens if node j is unreachable, partitioned, or adversarially non-responsive when node i needs `CrossCheck`? The paper's async model does not guarantee message delivery timing, so this mechanism either blocks (undermining availability) or must fall back to some default (which would need its own safety justification, not supplied here). Under C2 specifically, there is a further, subtler problem: `CrossCheck(i,j,s')` compares `Omega_i` and `Omega_j` at a specific state `s'`, but under asynchronous causal reordering it is not obvious the two nodes are evaluating the *same* causal instant of `s'` unless `CrossCheck` itself is causally anchored (e.g. via the vector-clock machinery of Section 2.3) - so this mechanism does not actually escape needing something like Causal Alignment either.

**Verdict:** theoretically sufficient, but at a cost that directly contradicts one of the paper's own stated design goals; not evaluated further here since the instructing memo scopes this section to necessary-condition identification, not cost-benefit adjudication.

### 3.2 Candidate (b): pairwise compatibility contracts at onboarding

**Formal shape.** Instead of runtime cross-checking, require every pair `i, j in N` to satisfy a design-time (or onboarding-time) compatibility check: whoever admits node j into the system verifies, by inspecting both `Omega_i` and `Omega_j`'s actual definitions (not their runtime outputs), that they agree on `S^ij` - i.e., a one-time proof obligation discharged by a verifier with full access to both definitions, rather than by a running node under C1's partial observability.

**Sufficiency.** If every pair is checked this way, Assumption 4 holds for every pair by construction, without needing Condition F (no single shared `Omega_G` is required - only pairwise agreement, potentially achieved differently for each pair) or a runtime protocol.

**Cost under C1.** This mechanism is not blocked by C1 at all: the verifier doing the pairwise check is, by construction, given both definitions directly (an epistemic situation unlike a *running node's* restricted observability) - this is structurally the same move the paper's own framework already makes for `Sspec`/`delta_spec` themselves (nodes do not need runtime visibility into the full global specification either; a designer is assumed to have it at specification time). The genuine cost is combinatorial and procedural, not epistemic: it requires `O(n)` pairwise checks for every new node admitted (checked against every existing node), and - since dynamic node membership is not addressed anywhere in the paper (carried-over open question from v0.1/v0.2) - there is no guarantee this checking actually happens as the system evolves; it is a governance/process requirement on whoever operates onboarding, not something the framework enforces structurally.

**A convergence worth noting:** pushed to its limit (every node checked against every other node, for a large or growing `N`), this mechanism starts to resemble Branch 1 again - if the pairwise contracts are all required to be mutually consistent across the whole node set, the simplest way to guarantee that in practice is for them all to derive from one common reference, which is exactly Condition F. Candidate (b) is genuinely more flexible than Branch 1 only insofar as it permits *ad hoc*, pairwise-only agreement without a single shared derivation - but nothing in this document establishes that such ad hoc agreement is easier to achieve or maintain than Condition F directly, for `N` of nontrivial size.

### 3.3 A third option, identified while evaluating (a) and (b): sound local approximation

Neither (a) nor (b) is fully satisfying - (a) is sufficient but costly and re-introduces synchrony; (b) is C1-robust but does not obviously scale better than Branch 1 itself. Considering what actually makes C1 a problem for Branch 2 (no node can check another node's *actual value* on a shared state at runtime) suggests a weaker, C1-robust alternative that neither the instructing memo nor v0.2 named explicitly:

**Definition (Sound Local Approximation).** Say `Omega_i` is a sound local approximation of a reference `Omega_G : Sspec -> {0,1}` (with respect to `pi_i`) if, for every `s in S^i_spec` and every `sigma` with `pi_i(sigma) = s`: `Omega_i(s) = 1 implies Omega_G(sigma) = 1`. (One-directional: `Omega_i` may be strictly more conservative than `Omega_G` - reject states `Omega_G` would allow - but never accept a state `Omega_G` would reject.)

**What this buys, without requiring Assumption 4's literal equality:** if every node's `Omega_i` (independently authored - no coordination between nodes required, no Condition F, no Condition C) is individually verified sound with respect to one *published* reference `Omega_G` at design/onboarding time, then Theorem 4's per-node conclusion (`Omega_i(sk)=1` along the accepted trace) upgrades to `Omega_G` actually holding at the corresponding global witness - i.e., local acceptance still genuinely implies ground-truth safety, node by node, *without* requiring any two nodes' `Omega_i`/`Omega_j` to be identical, agree pairwise, or even be aware of each other.

**Cost under C1:** none - this is, like (b), a one-time proof obligation discharged by whoever *authors* `Omega_i`, checking their own definition against a single published `Omega_G` they have full access to. Unlike (b), it requires no pairwise checking between nodes at all - each node's soundness proof is independent of every other node's, so it scales to a changing `N` without re-checking existing nodes when a new one joins (a genuine advantage over both (a) and (b) for the dynamic-membership problem this Track A series has repeatedly flagged as open and unaddressed by the paper).

**What it does not buy:** Sound Local Approximation is explicitly weaker than Assumption 4 - it does not establish `Omega_i = Omega_j`, only that both, whatever they individually decide, never accept an actually-unsafe state. Two nodes could still reach different accept/reject verdicts on the identical shared state (one conservative, one less so) without either being *wrong*. Whether that weaker guarantee is what "compositional safety" ought to mean, or whether the literal equality of Assumption 4 is doing real additional work this document has not identified, is left open (Section 5). It also does **not** address Lemma B (Section 2.5) at all - Sound Local Approximation is a Section-2.2-level (state-agreement) alternative, not a Section-2.5-level (trace-existence) one; the global-witness-gluing gap identified in Branch 1 is orthogonal to which state-agreement mechanism (Condition F+C, or Sound Approximation) is used, and remains open under this candidate exactly as it does under Branch 1 proper.

### 3.4 Summary

| Mechanism | Sufficient for Assumption-4-level agreement? | Blocked by C1? | Blocked by C2? | Cost |
|---|---|---|---|---|
| (a) Synchronous cross-check | Yes | No (not literally prohibited) | Partially (needs its own causal anchoring) | Reintroduces global synchronization the paper's design avoids; new liveness risk |
| (b) Pairwise onboarding contracts | Yes | No (verifier has full access, unlike a runtime node) | No (design-time only) | O(n) per new node; converges toward Branch 1 at scale |
| (c) Sound local approximation | No (weaker guarantee than Assumption 4) | No | No | Cheapest; scales to dynamic N; does not resolve Lemma B |

None of the three is shown here to be a complete solution: (a) and (b) are sufficient for Assumption-4-level agreement but costly in different ways; (c) is cheap and C1-robust but delivers a strictly weaker guarantee whose adequacy is unverified, and leaves Lemma B untouched regardless.

## 4. Implications for Governance Design (general only)

**Scope note, restated from the header:** this section speaks only in general terms about what follows, formally, from Sections 2-3, for *any* governance system built on p-DERS-style local invariant gates with multiple decision-making nodes. It makes no claim, and performs no investigation, about whether MoCKA's actual architecture is Branch 1, Branch 2, or something else; that determination is explicitly out of scope for this Track A document (it would be a Track B question). It is written because Human Gate did not rule out that Branch-2-shaped situations (independently-configured per-agent decision criteria) can occur in practice for *some* system of this general shape, which is what motivates having this menu of options worked out in the abstract, ready to be applied by whoever does the Track B-side investigation later, rather than performing that investigation here.

For any governance system with multiple decision-making nodes, each enforcing its own local safety predicate before accepting an action:

1. If every node's local predicate is derived from one shared, published specification via a fixed, consistent procedure (Branch 1 / Condition F), **and** the projections genuinely correspond to a shared underlying state space in the strong sense Condition C requires (not merely producing coincidentally-matching labels), pairwise safety-verdict agreement across nodes is provable (Lemma A) without any runtime coordination cost. This is the cheapest and strongest option, but it constrains how local predicates may be authored - they cannot be independently written per node.
2. If local predicates are, or may be, authored independently per node (Branch 2), pairwise agreement is not automatic and is not guaranteed by anything resembling the p-DERS paper's own architecture as published (v0.2 Section 3.3). Three general remediation shapes exist, with different cost profiles (Section 3.4): synchronous runtime cross-checking (sufficient, but reintroduces the synchronization cost the whole decentralized-verification approach was meant to avoid); pairwise design-time contracts (sufficient, C1-robust, but scales poorly and tends to converge back toward option 1 as the node count grows); or a one-directional soundness proof against a single published reference (cheap, C1-robust, scales to a changing node set, but only guarantees a weaker property than full pairwise agreement, and does not by itself address the separate, still-open trace-existence problem, Lemma B).
3. Regardless of which option is chosen, this document did not find a way to guarantee (Section 2.5, Lemma B) that per-node safety, however well-coordinated across nodes' individual observations, implies the existence of a single coherent global history simultaneously consistent with every node - this appears to be a genuinely separate obstacle from the state-and-order agreement problem Sections 2-3 otherwise resolve or narrow down, and it does not obviously go away under any of the three remediation options in point 2.

None of the above is a recommendation; it is a structural map of what would need to be true, and what would still remain unresolved even if it were.

## 5. Open Questions

1. **Lemma B (Global Trace Existence / Lifting)** - the central open item of this document (Section 2.5). Not proven, not disproven, no counterexample attempted in either direction. Whether it is provable under some additional, reasonable hypothesis on `{pi_i}` and `delta_spec`, or whether it can fail even under this document's full Branch 1 hypothesis set (Conditions F, C, and Causal Alignment), is unknown.
2. **Condition C (Coherent Overlap)'s relationship to Assumptions 1-3.** This document introduces Condition C as a new, additional hypothesis not present among Assumptions 1-4 as transcribed, and does not show it follows from Assumptions 1-3 (or from anything else in the paper). Whether it is implied by some reading of the paper this document has not considered, or is genuinely independent and would need to be separately imposed on any real projection family `{pi_i}`, is open.
3. **Whether Sound Local Approximation (Section 3.3) is an adequate substitute for Assumption 4, or whether the literal equality does load-bearing work this document has not identified.** Not resolved.
4. **Whether "compositional safety" itself should be defined at the strength of the Theorem in Section 2.4** (a single global witness trace) **or at the weaker strength Sound Local Approximation delivers** (no node ever accepts a ground-truth-unsafe state, without a unifying global witness). This document uses the stronger definition throughout Section 2 because it more directly generalizes Theorem 4's own existential claim, but does not argue this is the uniquely correct choice.
5. **Dynamic node membership**, carried forward yet again (v0.1 Open Question 4, v0.2 Section 5.2): still entirely unaddressed by the paper, and this document's Causal Alignment step (Section 2.3) inherits the same static-membership limitation v0.1's Lemma 1 already had.
