## 3. 核心の問い: 単発か、構造的か

**結論: 構造的である。ただし、その根拠は件数の多さではなく、コードの決定性にある。**

件数だけを見れば混入は1件であり、Human Gateが提示した判定基準("複数件あれば構造的")をそのまま当てはめると"単発"と読めてしまう。しかしその推論は成立しない。理由を以下に、根拠つきで示す。

### 3.1 生成器には承認ゲートが1行も存在しない(決定的根拠)

`tools/mocka_restrictions.py`のソース全体を機械的に検査した結果:

- ソース中に文字列"承認"は**一度も出現しない**
- 生成器の中に存在するif文は**ただ1つ**であり、それは`if "## 再発防止" in content:`(15行)のみ

すなわち、生成器には承認状態を判定する分岐が存在しないため、混入は"すり抜け"ではない。再発防止欄が存在する限り、承認欄の値が何であろうと**必ず**抽出される。これは確率的な事象ではなく、構造上の必然である。したがって、自動生成されたINCファイルの混入率は、サンプル数にかかわらず定義上100パーセントになる。

### 3.2 件数が1件に留まっている理由は、ゲートが機能しているからではない

`docs/governance/GPT_RESTRICTIONS.md`の生成日時は`2026-04-01 13:45:06`である。一方、INC-20260401-002.mdに5W1H分析が追記された自動分析日時は`2026-04-01 14:12:36`であり、生成の**27分後**である。

生成器は起動されるたびにファイルを全文上書き再生成する仕様であるから、生成日時が2026-04-01のまま更新されていないという事実は、その時刻以降、この自動更新チェーンが**一度も発火していない**ことを示す。本監査時点(2026-07-31)まで約4か月間、パイプラインは休止状態にある。

つまり、混入件数が1件に留まっているのは、承認ゲートが働いて残りを止めたからではなく、単にパイプラインがほとんど動いていないからである。パイプラインが再稼働すれば、CRITICAL/HIGH検出のたびに同じ混入が確定的に繰り返される。

### 3.3 誠実な限界表明

上記3.1は"今後発火すれば必ず混入する"ことの証明であって、"過去に何件混入したか"の証明ではない。過去の実績件数についての本監査の確度は、以下の理由により限定的である。

- 本リポジトリはshallow clone(`git rev-parse --is-shallow-repository`が`true`)であり、完全な履歴を追跡できない
- `docs/incidents/`配下の全ファイルおよびGPT_RESTRICTIONS.mdは、いずれも単一の一括同期コミット`72c163e`(auto sync 2026-07-21)で追加されており、それ以前の個別履歴がこのクローンからは見えない
- したがって、過去により多くのINCファイルが存在し後に削除された可能性は、否定も肯定もできない

"見つからなかった"ことは"起きなかった"ことの証拠ではない。過去実績としての件数は1件と確認できたが、それが履歴上の全件である保証はない。

## 4. 本監査で新たに判明した、2件の別種の欠陥

当初の調査対象(承認ゲート未接続)とは別に、同一パイプライン内で2つの構造的欠陥を新たに発見した。いずれもDC_20260731_001の記録時点では把握されていなかった事実である。

### 4.1 使える再発防止策が生成済みなのに、生成器の抽出窓の外にある

`tools/mocka_5w1h.py`は、パターンマッチによりインシデントごとの具体的な再発防止策を自動導出し、INCファイル末尾に"## 5W1H分析(自動生成)"セクションとして追記する。INC-20260401-002.mdの場合、実際に導出された内容は"orchestra経由(Playwright)に切替。APIキー依存を排除する"という、プレースホルダとは比較にならない実質的な内容である。

しかし生成器の抽出ロジックは、"## 再発防止"以降を次の"##"見出しまでで打ち切る(`section.split("##")[0]`、`tools/mocka_restrictions.py`:17行)。INCファイルの見出し順は以下の通りであり、"## 再発防止"の直後は"## 憲章違反条項"であるため、末尾に追記された5W1H分析は抽出窓に**入らない**。

```
## 発生日時 / ## 重大度 / ## 自動検知 / ## 発生内容 / ## 検知理由
## 再発防止      <- 抽出開始
## 憲章違反条項   <- ここで抽出打ち切り
## 承認 / ## 5W1H分析(自動生成) / ## パターン分類 / ## 自動分析日時
```

機械的に検証した結果、5W1H由来の文字列"orchestra経由"は、ファイル内には存在するが、生成器の抽出窓の中には存在しない。5W1Hエンジンは"## 再発防止"欄を書き換えて埋め戻す処理を持たないため、当該欄は"(要分析)"のまま残り続ける。

すなわち、使える答えがシステム内で既に生成・保存されているにもかかわらず、生成器が別の場所を見ているために一度も使われていない。

### 4.2 実行順序が逆であり、仮に埋め戻しても当該回には反映されない

`tools/mocka_risk_engine.py`の実行順序は以下の通りである。

- 155行: `os.system(f"python {RESTRICTIONS}")` (GPT_RESTRICTIONS.md再生成)
- 159行: `os.system(f"python {w5h1_script}")` (5W1H分析の追記)

再生成が先、分析が後である。したがって、仮に4.1の欠陥を修正して5W1Hが"## 再発防止"欄を埋め戻すようにしたとしても、その回のGPT_RESTRICTIONS.mdは既に古いプレースホルダで上書き済みであり、当該回には反映されない。次にCRITICAL/HIGHインシデントが発生して再生成が走るまで、公式ファイルは未分析のままとなる。

## 5. 設計案の選定への含意(推奨は行わない)

`track_B_gpt_restrictions_reverification_design_v0.1.md`で提示した4案は、いずれも3章の欠陥(承認ゲート未接続)を対象としたものであり、本監査で新たに判明した4章の2欠陥は対象外である。以下は事実関係の整理であり、案の選定・推奨は行わない。

- 案(d)(既存の承認欄を実効ゲート化)は、3章の欠陥には直接対応するが、4.1(抽出窓の外に答えがある)および4.2(実行順序)には対応しない。案(d)のみを適用した場合、INC-20260401-002は"未検証・レビュー待ち"に正しく分離されるが、既に生成済みの実質的な再発防止策は依然として使われないままとなる
- 4.2の実行順序は、155行と159行の入れ替えという局所的な変更で解消しうる形をしているが、その妥当性(5W1Hの結果を無検証で正式な禁止事項へ昇格させてよいのかという、3章とまったく同じ論点が再発する)は未評価である
- 本監査の結果は、是正対象が当初想定の1点(承認ゲート)ではなく少なくとも3点(承認ゲート未接続、抽出窓のずれ、実行順序)であることを示している。是正範囲の再定義が必要かどうかはHuman Gate判断事項である
