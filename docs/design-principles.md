# 設計思想 — PC盤でも耐える条件

プロトタイプを PC盤へ移すための合格基準です。ここを満たさないコードは昇格させません。

## 1. 障害に耐える
- 入力が不正・欠損しても例外で落ちず、既定値またはエラー表示で継続する。
- 描画ループ内で発生した例外は、ループ全体を止めず当該フレームのみ捨てる。
- 外部データ（JSON等）は必ずスキーマ検査を通す。

## 2. 資源を食いつぶさない
- メモリ：長時間（例：30分）実行してもヒープが単調増加しないこと。
- 描画：オブジェクト数を増やしても、フレーム時間の悪化を計測で示せること。
- 破棄：タイマー・リスナー・GPUリソースは停止時に必ず解放する。

## 3. 再現可能
- 乱数はシード固定可能にし、同じ入力で同じ結果になること。
- 設定値はコードに埋め込まず、外部設定で差し替えられること。

## 4. 影響を外に出さない
- 既定で外部通信・ファイル書き込み・グローバル状態の変更をしない。
- 必要な場合は明示的な設定でのみ有効化し、その旨をログに残す。

## 5. 観測できる
- 異常・性能値をログ／カウンタとして出力する。
- 「動いた」ではなく、測定値（フレーム時間・メモリ・エラー件数）で判定する。

## 合格基準（昇格条件）

| 項目 | 基準 |
|---|---|
| 構文・静的確認 | エラー0件 |
| 正常系試験 | 全件合格 |
| 故障注入試験 | 不正入力でもクラッシュ0件 |
| 長時間試験 | メモリ増加が許容範囲内 |
| 性能 | 目標フレーム時間を満たす（数値は別途定義） |
| 隔離確認 | 外部通信・外部書き込みが0件 |

数値目標（フレーム時間・メモリ上限など）は、Geminiの実装を受領した後に確定させます。
