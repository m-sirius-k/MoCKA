## 0. Summary

The exhaustive sweep of 288 combinations verifies that under the explicitly
defined finite state space, **only one execution path is possible**: past ALLOW
with all premises unchanged.

This audit defines what "exhaustive" means, what it encompasses, and what it
deliberately does not claim.

---

## 1. State Space Definition

The 288-combination sweep explores all legal combinations of 7 dimensions,
each representing an observable parameter of the re-evaluation gate.

### 1.1 Dimension: Past Decision

| Variable | Values | Cardinality | Semantics |
| -------- | ------ | ----------- | --------- |
| past_decision | ALLOW, BLOCK, UNKNOWN | 3 | Verdict stored from prior evaluation |

**Representation:** `PastDecision` enum (type-safe)
**Rationale:** Covers all possible stored verdicts
**Out of scope:** Decision timestamp, decision maker identity, decision rationale

### 1.2 Dimension: Evidence State

| Variable | Values | Cardinality | Semantics |
| -------- | ------ | ----------- | --------- |
| evidence | ORIGINAL, CHANGED | 2 | Whether evidence digest matches present |

**Representation:** digest comparison only; ORIGINAL or CHANGED
**Rationale:** Gate observes only digest; content validation is out of scope
**Out of scope:** Evidence content, quality, provenance, weight

### 1.3 Dimension: Temporal Validity

| Variable | Values | Cardinality | Semantics |
| -------- | ------ | ----------- | --------- |
| validity | FUTURE, PAST | 2 | Whether validity_until timestamp is after present |

**Representation:** Timestamp comparison; FUTURE or PAST
**Rationale:** Gate observes only temporal boundary; clock time is fixed
**Out of scope:** Confidence in timestamps, clock drift, timezone handling

### 1.4 Dimension: Authority State

| Variable | Values | Cardinality | Semantics |
| -------- | ------ | ----------- | --------- |
| authority_state | VALID, LOST, REVOKED | 3 | Operational status of authority |

**Representation:** Enum value; VALID / LOST / REVOKED
**Rationale:** Covers all state transitions observable to gate
**Out of scope:** Authority legitimacy, credentials, trust basis

### 1.5 Dimension: Authority Identity

| Variable | Values | Cardinality | Semantics |
| -------- | ------ | ----------- | --------- |
| authority_id | ORIGINAL, OTHER | 2 | Whether authority matches past decision |

**Representation:** String comparison; ORIGINAL or OTHER
**Rationale:** Gate observes identity match/mismatch only
**Out of scope:** Authority hierarchy, delegation chains, authority relationships

### 1.6 Dimension: Context Identity

| Variable | Values | Cardinality | Semantics |
| -------- | ------ | ----------- | --------- |
| context_id | SAME, DIFFERENT | 2 | Whether context identifier matches past |

**Representation:** String comparison; SAME or DIFFERENT
**Rationale:** Gate uses context_id as mechanical boundary
**Out of scope:** Context semantics, context hierarchy, context relationships

### 1.7 Dimension: Context Digest

| Variable | Values | Cardinality | Semantics |
| -------- | ------ | ----------- | --------- |
| context_digest | ORIGINAL, CHANGED | 2 | Whether context content digest matches past |

**Representation:** Digest comparison within same context_id; ORIGINAL or CHANGED
**Rationale:** Gate observes only digest within same context
**Out of scope:** Context content interpretation, context boundary semantics

## 2. Combination Formula

### 2.1 Formal Expression

```
Total Combinations = |past_decision| × |evidence| × |validity| × |authority_state| 
                     × |authority_id| × |context_id| × |context_digest|

                   = 3 × 2 × 2 × 3 × 2 × 2 × 2
                   = 288
```

### 2.2 Factorization

```
288 = 3 * 2^5 * 3
    = (3 decision values) × (2^5 binary/ternary changes) × (3 authority states)
    = (3) × (2 × 2 × 2 × 2 × 2) × (3)
```

Alternative grouping:

```
288 = (3 × 2 × 2 × 3) × (2 × 2 × 2)
    = (36 past decision × authority state combinations)
      × (8 orthogonal premise combinations)
```

### 2.3 Enumeration

The 288 cases are generated by `itertools.product()`:

```python
for past, ev, valid, astate, aid, cid, cdig in itertools.product(
    (PastDecision.ALLOW, PastDecision.BLOCK, PastDecision.UNKNOWN),  # 3
    (EV_ORIGINAL, EV_CHANGED),                                       # 2
    (VALID_FUTURE, VALID_PAST),                                      # 2
    ("VALID", "LOST", "REVOKED"),                                    # 3
    (AUTH_ORIGINAL, AUTH_OTHER),                                     # 2
    (CTX_ID, CTX_ID_OTHER),                                          # 2
    (CTX_ORIGINAL, CTX_CHANGED),                                     # 2
):
    # Assess combination
```

Each combination generates one assessment instance.

## 3. Exhaustiveness Boundary

### 3.1 What IS Exhaustive

**Statement:**
The sweep is exhaustive over all combinations of 7 explicitly defined
dimensions, where each dimension takes on all its declared legal values.

**Formally:**
Exhaustive(C) ≡ ∀c ∈ C . c is a unique member of the Cartesian product
D1 × D2 × D3 × D4 × D5 × D6 × D7, where each Di is fully specified.

**Verification:**
- 288 unique combinations generated via itertools.product()
- No duplicates or omissions
- All 7 dimensions iterated in their entirety
- No conditional skipping of combinations

### 3.2 What IS NOT Exhaustive

#### 3.2.1 Evidence Content

**Out of scope:** The actual content, provenance, quality, or validity of evidence.

**Why:** Gate operates only on digest comparison. A different evidence set with
the same digest will not be distinguished. Two sets with identical content but
computed digests differently will be distinguished mechanically but not
semantically.

**Implication:** The gate is exhaustive over digest values, not evidence quality.

#### 3.2.2 Authority Legitimacy

**Out of scope:** Whether an authority is truly authorized, trustworthy,
properly delegated, or has legitimate standing.

**Why:** Gate observes only authority_id and authority_state fields. It does
not validate authority credentials, chain of custody, or organizational position.

**Implication:** The gate is exhaustive over observable authority fields, not
over legitimate authority spaces.

#### 3.2.3 Re-evaluation Outcome

**Out of scope:** What the re-evaluation would determine. The gate only flags
that re-evaluation is necessary.

**Why:** Gate responsibility ends at "re-evaluate required". Actual re-evaluation
is outside this gate's scope.

**Implication:** The sweep does not test whether "RE_EVALUATE then ALLOW" is
correct. It only tests whether RE_EVALUATE was correctly requested.

#### 3.2.4 Temporal Dynamics

**Out of scope:** How validity windows move as time passes. The gate operates
with fixed timestamps.

**Why:** Clock is fixed to 2026-08-28T12:00:00Z. Decisions made at different
times or validity windows that shift are not tested.

**Implication:** The sweep is exhaustive for static timestamps, not for time
progression or duration variations.

#### 3.2.5 Context Boundary Semantics

**Out of scope:** What constitutes a valid context, how contexts relate, or
what "context mismatch" means semantically.

**Why:** Gate treats context as mechanical identifiers and digests. No context
ontology is implemented.

**Implication:** The sweep is exhaustive over context field values, not over
context semantic spaces.

#### 3.2.6 Implementation Variants

**Out of scope:** Other gate designs, alternative eligibility rules, or
different execution policies.

**Why:** Single gate implementation tested. No strategy variants included.

**Implication:** Sweep verifies this gate's behavior, not universal gate
behavior.

### 3.3 Explicitly Unexhausted Dimensions

| Dimension | Cardinality in Real World | Cardinality in Sweep | Reason |
| --------- | ----------------------- | ------------------- | ------ |
| Evidence content | Unbounded | 1 (digest only) | Out of scope |
| Authority legitimacy | Unbounded | 1 (state/ID only) | Out of scope |
| Time progression | Continuous | 1 (fixed clock) | Reproducibility |
| Context ontology | Domain-dependent | 1 (mechanical IDs) | Out of scope |
| Implementation | Multiple possible | 1 (single gate) | Test-specific |
| Authority trust basis | Context-dependent | 1 (state only) | Out of scope |

## 7. Exhaustiveness Statement

> **Within the explicitly defined finite state space** (7 dimensions, 288
> combinations), the sweep is **exhaustive over all legal input combinations**.
>
> **Exhaustiveness does NOT extend to:**
> - Evidence content or quality (digest only)
> - Authority legitimacy or trust (state/ID only)
> - Re-evaluation correctness (gate only flags necessity)
> - Temporal dynamics (fixed clock)
> - Context semantics (mechanical ID only)
> - Implementation variants (single gate)
>
> **The sweep guarantees:** Under these premises and this gate design, exactly
> one execution path is possible, and it requires all five premise categories
> to remain unchanged.
