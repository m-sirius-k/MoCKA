## 4. 修正順序案の比較(Phase 7)

推奨順位は付けない。各案の性質を事実として記録する。

### 案A: D-4 -> D-5 -> D-2 -> D-3 -> D-1

| 観点 | 内容 |
|------|------|
| メリット | 最初にM-1(遮蔽)を解除するため、以降の各是正が通常経路で観測できる。D-4の実害(event_id全損)がINC生成の有無と無関係に進行している点(先行文書4.1 経路1)に最も早く手当てが入る |
| デメリット | D-5是正からD-1是正までの区間、承認ゲートが無いままINC生成が有効になる。手順が5段階で最も長い |
| リスク | **露出窓**: D-5是正後・D-1是正前に本番実行すると、未承認INCが公開ファイル(origin/main到達済み)へ一斉掲載される。実測ではRun Bで6件が同時生成され、そのすべてが `(要分析)` として掲載された。窓の間に実行が起きないことを運用で担保する必要がある |
| 検証難易度 | 低。各段階の効果を通常入力で観測できる。ただしD-4段階の検証はevents.csvを共有する58ファイルへの影響確認を含むため、この1段階だけは重い |

### 案B: D-2 -> D-3 -> D-1 -> D-4

| 観点 | 内容 |
|------|------|
| メリット | 公開経路の正しさ(順序・内容・可否)を先に確定させる。D-1完了までINC生成はD-5により抑止されたままなので、案Aのような露出窓が生じない |
| デメリット | **本案にD-5が含まれていない**。指示書記載のとおり記録する。D-5未是正のままではINC生成が停止し続けるため、D-4を是正しても(BOMが解消されevent_idが復活しても)重複判定の部分一致・空キー扱いの不健全さは残る。全欠陥の解消には本案の後にD-5が別途必要である |
| リスク | (a) D-2/D-3/D-1の是正が、通常経路では一切観測できない状態で3段階進む(制約C-1)。誤りが混入しても最終段階まで露見しない。(b) 最終段のD-4完了時点で遮蔽が解除され、それまでの3段階の是正結果が初めてまとめて本番へ現れる。問題が出た場合、どの段階に起因するかの切り分けが難しい |

### 案C: 並列修正(一括是正)

| 観点 | 内容 |
|------|------|
| メリット | 露出窓が生じない。中間状態が本番へ現れない。手戻りが少ない |

### 4.1 3案に共通する事項

- いずれの案でも、D-1未是正の状態でINC生成が有効になる区間が存在するか否かが
  露出リスクの分かれ目となる。案Aは存在し、案B・案Cは存在しない
- いずれの案でも、D-2とD-3は同時に完了しない限り最終出力は是正されない
  (先行文書4.2 ケース2/3)。途中段階を"是正済み"と記録する際は、
  出力が変わっていないことを併記しないと誤読を招く
- いずれの案でも、GPT_RESTRICTIONS.md は origin/main へ push される公開ファイルで
  あるため、中間状態がpushされないことの担保が必要である
