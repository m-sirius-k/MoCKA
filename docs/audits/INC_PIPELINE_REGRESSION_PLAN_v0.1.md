## 1. 試験環境の方式

先行調査(Phase 4)で用いた隔離サンドボックス方式をそのまま踏襲する。

```
scratchpad/<name>/
  data/events.csv            <- 本体からコピーした入力(fixture)
  docs/incidents/            <- 本体からコピーしたINC群
  docs/governance/           <- 出力先
  tools/*.py                 <- 本体からコピー。パス定数のみサンドボックスへ書換
```

この方式を採る理由(先行調査で実証済みの性質)。

- tools/ の3スクリプトはパス定数がファイル冒頭に集中しており(risk_engine.py:6-8、
  5w1h.py:6-7、restrictions.py:5-6)、定数置換のみで隔離できる
- 本体の data/events.csv / docs/incidents/ / GPT_RESTRICTIONS.md を一切変更せずに
  全経路をend-to-endで実行できる
- 本番の data/events.csv をそのまま入力とした検証は D-5 の遮蔽により成立しない
  (Run Aで実測: INC 0件のため下流が起動しない)。合成入力が必須である

注意: tools/mocka_restrictions.py は import 時に `generate_restrictions()` を実行する
(restrictions.py:58)。単体importによる関数呼び出しでの試験は副作用を伴う。
