### 発見時の状況

**発生イベント**: E20260705_732301073f4bd

**問題の概要**:
- SESSION_20260705_124108 で mocka_decision_write/mocka_integrity_write 系の MCP ツールがセッションのツール一覧に見当たらない状態が発生
- DC_20260705_006 の Decision Ledger 反映が後続セッションまで持ち越された
- 初期仮説: サーバー側の障害
- 実際の原因: セッション側の MCP Tool レジストリキャッシュが、サーバー再起動後も更新されないという既知の性質

**根本原因の判明**:

2026-07-05 の調査結果、以下が確定した：

1. mocka_mcp_server.py の /mcp エンドポイント (959-975 行目) は、**ステートレスな HTTP リクエスト・レスポンス方式**
2. SSE / WebSocket 等の永続ストリームではない
3. MCPプロトコル標準の `capabilities.tools.listChanged` + `notifications/tools/list_changed` (サーバー→クライアント非同期push通知) は、この設計の上では成立不可能
4. よって、サーバー再起動後にクライアント側のツール一覧キャッシュが自動更新される仕様は実装不可

### 当時の対応状況

**内容**: 「MCP Tool Registry Drift対応方針」セクションを CLAUDE.md に追記

#### 対応 3: ハッシュベース検知設計 (IC_20260705_018 続報)

**手法**: 既存の `mcp_schema_hash.json` (data/tic/) を流用

**運用フロー**:

1. **セッション開始時**: `mcp_schema_hash.json` のハッシュ値を「セッション基準ハッシュ」として記録
2. **書込ツール不在検知時**: 
   - 1回だけ再試行
   - 再試行前後で `mcp_schema_hash.json` を再取得
3. **ハッシュ比較**:
   - **変化あり** → サーバーコード変更の証拠。通常の Drift 対応方針を適用 (再試行 1 回 → Incident 化 → セッション内制限)
   - **変化なし** → Drift（新規セッションで解消）ではなく別種の問題。異なるタイプで Incident 化

## 関連する Decision Ledger 記録

### DC_20260705_006: last_decision の意味定義改訂

**タイトル**: last_decision の意味定義を events.db 参照から Decision Ledger 参照へ改訂

**背景**: gateway/context_builder.py の `_last_decision()` が events.db 生イベントを参照しており、RISK_SCORE_UPDATED 等の非 decision イベントが「last_decision」として返される問題

**決定**:
- Decision Ledger Schema v1 を唯一の decision source of truth として確定
- events.db は observation/log layer に限定
- last_decision の定義を「最新イベント」から「最新の承認済み decision」に改訂
- event と decision を同一視しない境界原則を導入

**ステータス**: Active  
**実装**: 設計原則のみ。コード変更は別途承認待ち

### DC_20260705_007: ハッシュベース検知策の採用

**タイトル**: MCP Tool Registry Drift 再発防止策として、mcp_schema_hash.json 活用によるハッシュベース検知を採用

**背景**: IC_20260705_018 で確定した Drift をどう防止するか

**検討した代替案**:
1. ❌ `capabilities.tools.listChanged` + 非同期 push 通知の実装 → サーバー側トランスポート層の作り直しが必須（スコープ超過）
2. ❌ Relay と統合して遅延状態モデルとして再定義 → 実装上別層、統合対象ではない

**採択**: 既存の `mcp_schema_hash.json` をハッシュベース検知シグナルとして流用

**メリット**:
- 既存資産の再利用 → 新規インフラ不要
- mocka_mcp_server.py のコード変更不要 → 稼働中本番環境への実装リスクなし
- CLAUDE.md への手順追記のみで即座に運用開始可能

**ステータス**: Active  
**実装**: CLAUDE.md への手順追記済み
