# MoCKA Audit Standard Draft v0.1

位置づけ: R01実行指示書「MoCKA Audit Standard v1.0 制定プロジェクト」Phase A-3(Draft Preparation)に基づく。入力資料は`AUDIT_PROCESS_EXTRACTION_v0.1.md`(Phase A-1)・`AUDIT_PROCESS_VERIFICATION_v0.1.md`(Phase A-2)、およびPhase A-2完了時点で発生した停止に対するR01裁定(2026-07-04)である。

R01裁定の内容:
1. Audit Standardの正式フェーズは4フェーズ(Fact Collection/Analysis/Decision Preparation/Final Decision)のままとする。
2. Evaluationは監査テーマ固有の任意工程(Optional Stage)として付録または補足節に記載する。
3. Analysisは「直前フェーズの正式成果物」を入力と定義する。
4. フェーズ移行は特定個人ではなく「承認権限者」によって行われるものと定義する。

本ドラフトは上記裁定と、今回実証された3件の監査テーマ(Vocabulary Audit/Cross Reference Audit/CI Failure)の実績のみを構成要素とする。今回実証されていない制度は追加していない。

---

## 1. 目的

本標準は、Vocabulary Audit・Cross Reference Audit・CI Failureの3件の監査テーマを通じて実際に運用され、承認権限者によるFinal Decision(2026-07-04)にて完了が確認された監査プロセスを、再利用可能な標準手順として文書化するものである。

## 2. 適用範囲

MoCKAにおいて、事実の収集から承認権限者による最終裁定に至るまでを扱う監査案件。本標準は今回実証された3件の監査テーマ(Vocabulary Audit・Cross Reference Audit・CI Failure)の実績のみに基づく。今回実証されていない監査類型への適用可否は本標準の範囲外とする。

## 3. 基本原則

- 各フェーズの責任範囲を分離し、事実・分析・裁定を混在させない。
- 各フェーズの実行担当者は、割り当てられたフェーズの目的を超える評価・改善案・優先順位付け・採否判断を行わない。
- 各フェーズは、直前フェーズの正式成果物の完了をもって開始される。
- 記録なき作業はMoCKAとして存在しない(MOCKA_OVERVIEW.json記載のConstitution原則)。各フェーズの着手・完了はmocka_write_eventによる記録を伴う(今回の3件の監査テーマすべてで確認された運用)。

## 4. 監査4フェーズ

### 4.1 Fact Collection

- 目的: 対象事案に関する事実の収集・提示に限定し、評価・改善案・原因推定・採否判断を行わない。
- 完了条件: 収集した事実を提示した時点で作業を停止し、承認権限者の判断を待つこと。

### 4.2 Analysis

- 目的: 直前フェーズの正式成果物のみを入力とし、新規調査は行わない。複数の監査テーマを並行して扱う場合、各テーマは独立分析として扱い、一方の結論を他方の根拠に用いない。修正案・実装案・優先順位・原因断定は行わない。
- 入力: 直前フェーズの正式成果物(Fact Collectionの成果物、または当該監査テーマにOptional Stageが存在する場合はその成果物)。
- 完了条件: 確認できた事実/事実から導かれる分析/未確認事項/承認権限者の判断が必要な事項を整理した時点で完了とする。

### 4.3 Decision Preparation

- 目的: 承認権限者の裁定に必要な資料を整理する。採択・却下・優先順位付け・修正案・実装案の記載、および裁定の代行は行わない。
- 入力: Analysisフェーズの正式成果物のみ。
- 完了条件: Analysis要約/裁定事項/判断後の影響範囲/未判断事項を整理し、修正案・優先順位・採否判断を含めず、最終判断をすべて承認権限者へ委ねた時点で完了とする。

### 4.4 Final Decision

- 目的: 提出されたDecision Preparation成果物に対する裁定(承認・却下等)、状態の確定、次工程の指定を行う。
- 入力: Decision Preparationフェーズの正式成果物。
- 完了条件: 対象案件について裁定・状態・次工程が示され、監査サイクルの完了が確認された時点で完了とする。

### フェーズ移行

各フェーズから次フェーズへの移行は、承認権限者による移行指示をもって行われる。移行指示の発出形式(指示書・直接指示等)は本標準では定めない。

## 5. 各フェーズの責任

- Fact Collection: 実行担当者。事実の収集・提示のみ行い、評価・判断は行わない。
- Analysis: 実行担当者。直前フェーズの正式成果物のみを対象とした分析を行う。
- Decision Preparation: 実行担当者。承認権限者の裁定資料の整理のみ行う。
- Final Decision: 裁定者(承認権限者)が裁定を行い、実行担当者が記録する。

## 6. 成果物

各フェーズは以下の構成を持つ文書として記録する(今回実証された構成)。

- Fact Collection: 事実の一覧。位置づけの明記、事実節、「以上が収集した事実である」旨の明記により構成される。
- Analysis: (1)確認できた事実 (2)事実から導かれる分析 (3)未確認事項 (4)承認権限者の判断が必要な事項、の4節構成。
- Decision Preparation: (1)Analysis要約 (2)裁定事項 (3)判断後の影響範囲 (4)未判断事項、の4節構成。
- Final Decision: 案件ごとの裁定・状態・次工程、および監査サイクル完了宣言。

## 7. 完了条件

各フェーズの完了条件は第4節(4.1~4.4)に記載の通り。監査サイクル全体の完了条件は、対象とするすべての監査テーマについてFinal Decisionが発出され、監査サイクルの完了が宣言されたことをもって満たされる。

## 8. 運用上の注意

- Optional Stage(監査テーマ固有の任意工程): 監査テーマによっては、Fact CollectionとAnalysisの間に、当該テーマ固有の任意工程が介在する場合がある。今回のVocabulary Auditトラックでは、Fact Collection(事実収集フェーズ)とAnalysisの間に、A~D評価・論点整理を行うEvaluation(評価工程)が存在した。この工程は本標準の正式フェーズ(第4節)には含めない。実施する場合、Analysisフェーズが定義する「直前フェーズの正式成果物」は、このOptional Stageの成果物となる。
- Optional Stageの完了条件・様式は本標準では定めない。今回実証された例(Vocabulary Audit Evaluation)は、評価基準の明文化・層別評価表・論点整理(優先順位を含まない)という構成を取ったが、これは当該監査テーマ固有の運用であり、他の監査テーマに一律に適用されるものではない。
- フェーズ移行の発出形式(指示書・直接指示等)は監査テーマにより異なりうる。本標準は発出形式を問わず「承認権限者による移行指示」として扱う。
