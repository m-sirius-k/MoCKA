## 5. 整合性確認

### 5.1 確認結果

| # | 確認項目 | 結果 |
|---|---|---|
| 1 | **S-1 から S-7 との整合** | **整合**。X-3 が判定値の変更・統合・上書きを明示的に否定しており、S-1 / S-2 / S-4 / W-8 を維持する。本裁定は S-4 の「その先」を X-2 / X-4 / X-12 で定めるものであり、S-4 自体を変更しない |
| 2 | **必要条件 (v0.6 5.5.2 / 5.5.4) への非影響** | **影響なし** (1.3)。判定値・必要条件の判定対象8項目・候補の状態の計算はいずれも不変 |
| 3 | **責務分離の維持** | **維持**。X-1 が意味論を HG-C10 に、X-8 が比較・変換ルールを HG-C14 に明示的に残している |
| 4 | **HG-C10 依存の処理** | **処理済**。項目3 の A により先行裁定とし、意味論を保持した。本 Record は不一致の意味に踏み込まないため、HG-C10 がいずれの選択 (定義・設計レベルのみ / 実装状態も含む) を採っても矛盾しない |
| 5 | **Decision Immutable 原則** | **適用**。第7章に明記 |
| 6 | **自動裁定化リスクの非該当** | **非該当**。X-6 が再発件数等による自動昇格を禁止し通知トリガーに留めている。X-9 / X-10 が検知 (Core) と確定 (Finalization) を分離している。承認を自動生成する条項は本 Record に存在しない |

### 5.2 追跡単位と比較単位の区別 (Confirmed)

**X-4 の「発生経路単位」は記録・追跡の粒度であり、HG-C14 が定める比較単位ではない。**

| 概念 | 内容 | 帰属 |
|---|---|---|
| **追跡単位** | 不一致が発生した事実を **どの粒度で記録・追跡するか** | **HG-C09 (X-4)。確定済** |
| **比較単位** | 系統単位の C2-a と経路単位の C2-b を **何と何で比較して不一致と判定するか** | **HG-C14。未定義 (X-8)** |

**両者を同一視しないこと。** X-4 は記録側の粒度を定めたにすぎず、
不一致の判定規則そのものは HG-C14 の裁定を待つ。

### 5.3 CLAUDE.md 規定との整合 (Confirmed)

`.claude/CLAUDE.md` は「recurrence_registry の記録件数を根拠に、検知の閾値変更・運用ルール強化・制度昇格を
自動的に行うこと」を禁止している。**X-6 はこの規定と一致する。**

### 5.4 入力資料からの記述差分 (確認事項)

**本裁定文と入力資料 `G5_HGC09_DECISION_INPUT_v0.1.md` の間に、項目の記述差分がある。
記録するものであり、裁定の再検討を求めるものではない。**

| # | 差分 | INPUT v0.1 | 本裁定 |
|---|---|---|---|
| CH-1 | **項目1 の候補 B の記述** | B = Integrity Ledger 記録対象 | **B = 台帳記録対象** (特定台帳を指定しない一般化された記述) |
| CH-2 | **項目2 の論点そのもの** | 不一致情報の **記録先** (A: Integrity Ledger / B: Incident 系記録 / C: Decision 関連記録 / D: 複数記録層) | **不一致の追跡単位** (B = 発生経路単位) |

**CH-2 の帰結:** INPUT 項目2 が問うていた **記録先の特定**は、本裁定文では直接には確定していない。
X-11 / X-12 により **新規 Pending 台帳を作成せず既存 Event / Ledger 体系を利用する**ことは確定したが、
既存系統のいずれを用いるかは一意に定まらない。6.3 の残存未確定 RU-1 として記録する。
