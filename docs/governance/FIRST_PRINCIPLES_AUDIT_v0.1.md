# First Principles Audit v0.1

位置づけ: 博士指示（2026-07-03、Task-J）に基づき新規作成。MoCKAの第一原理（すべてのGuaranteeがそこから導かれる根源的な公理）を明文化する。

**重要な前提:** MoCKAには現時点で「第一原理」として明示的に確定した公理集は存在しない（要確認）。本ファイルが提示するP1〜P5は、Constitution5原則・Human-First原則・本日の一連の監査（CONCEPT_AUDIT_v0.1、GUARANTEE_MATRIX_AUDIT_v0.1等）から逆算的に抽出した**提案**であり、MoCKAの公式な公理として確定しているものではない。人間承認を経て初めて制度として確定する。実装は一切含まない。

## 第1部: 現状把握

### 1.1 出発点となる既存の明文化された原則

- **Constitution5原則**（`MOCKA_OVERVIEW.json`）: Event ledger is append only / All decisions preserve 5W1H / Infield is internal memory / Outfield is collaborative interface / Event history is the single source of truth
- **哲学の核**（同ファイルphilosophy節）: 「AIを信じるな、システムで縛れ」（core）、「自由を許し、必ず記録し、証明する」（method）、「事故→記録→分析→制度化→文明の進化」（incident）、「失敗は資産になる」（failures）
- **Human-First原則**（`docs\caliber\LOOP_DESIGN_PRINCIPLES.md`第5節）: 「人間の意図=絶対座標（Origin）、AIの提案=候補（Candidate）、AIの決定=存在しない」
- **file_edit_rule**（`MOCKA_OVERVIEW.json`）: 「記録なき作業はMoCKAとして存在しない」

これらは相互に重なりを持ちながら、異なる文書に分散して存在する。第一原理の抽出とは、これらの背後にある共通の公理を見つける作業である。

G1存在保証、G2不変性・改ざん検知保証、G3網羅性保証、G4実行前安全性保証、G5人間最終決定保証、G6暴走・停滞検知保証、G7品質・妥当性保証、G8単一正本保証、G9権限分離保証、G10文脈・経験継承保証。これらは第一原理の「観測結果」であり、それ自体は第一原理ではない、という整理を本監査の前提とする。

## 第2部: 提案 — 第一原理（P1〜P5、提案段階）

### 2.1 抽出した5つの第一原理

| 記号 | 第一原理 | 根拠となる既存原則 |
|---|---|---|
| P1 | 信頼を制度で代替する。個々のAIの善意・能力・一貫性に依存せず、構造（システム）で行動を縛る | 「AIを信じるな、システムで縛れ」 |
| P2 | すべての行為は事後に検証可能でなければならない。検証できない行為は、行われなかったことと区別がつかない | 「記録なき作業はMoCKAとして存在しない」、Constitution「Event ledger is append only」「Event history is single source of truth」 |
| P3 | 最終的な意思決定権は常に人間にある。AIの決定という概念自体が存在しない（AIは候補を提示するのみ） | Human-First原則そのもの |
| P4 | 失敗・逸脱は排除ではなく記録と制度化の対象である | 「失敗は資産になる」「事故→記録→分析→制度化→文明の進化」 |
| P5 | 拡張は既存の恒久構造を破壊しない形でのみ許容される | 単一ルート規則（MCP配置ガード）、Freeze原則、Task Orchestrator Layerの「外付け・未接続」実装という前例、TODO_364の経路増殖回避原則 |

**この5分類の妥当性そのものが要確認である。** 特にP2とP4は「記録」という共通の実装手段を持つため、実際には1つの原理の異なる側面（P2=記録の必要性、P4=記録された失敗の扱い方）である可能性があり、統合できるかもしれない。逆にG10（文脈・経験継承保証）はP1〜P5のどれからも直接には導けず、独立した第六の原理が必要な可能性がある（後述2.4）。

### 2.2 MoCKAが絶対に保証したいもの

上記5原理から直接導かれる「絶対に譲れない」保証は以下と考えられる。

- P3から: 人間の意図に反してAIが最終決定を下すことは、いかなる効率化の理由があっても許容しない
- P1から: AIの自己申告・自己評価のみで安全性を確認したことにはしない（GL7のような外部構造による強制）
- P2から: 「起きたことが起きなかったことと区別できない」状態を作らない（記録の欠落を許容しない）

### 2.3 意図的に保証しないもの

MoCKAが明示的に「保証しない」と宣言している、あるいは保証の対象外と位置づけている事項を以下に整理する。これらは実装漏れではなく、設計上の意図的な選択である。

- **参照整合性（Referential Integrity）**: KN-004 Registryにおいて「atlas.from/to、classification.target_id等は文字列パターンのみ検証し、存在確認はしない」ことが仕様として非保証と確定している（README.mdに明記済みとの記録が既存メモにある。本監査では実ファイルを再確認していない・要確認）
- **AIの自動決定・自動実行・自己最適化ループ**: LOOP_DESIGN_PRINCIPLES第3節「自動展開禁止」により、これは「保証しない」のではなく「起きないことを保証する」という否定形の保証（P3の裏返し）
- **override_requestedの絶対優先権**: Decision Policy v0.1で「絶対優先権（権利）ではなく、優先してほしいという要求」と明記。要求者に保証された優先権は存在しない
- **Decision Policy自身の実行・保存**: 「判定するのみ」「実行しない」「保存しない」と明記されており、これらの責務を持たないことが意図的に宣言されている（P5・P9的な権限分離の裏返し）
- **KN-004 Registryにおける横断的競合の自動検出**: 「domain x categoryをまたぐ横断的競合は自動検出せず、knowledge_relationshipsへの明示的記録（人間判断）に依存する」と明記（DECISION_POLICY_v0.1.md第5節）。これはP3（人間最終決定）を優先し、自動化の範囲を意図的に制限した例

### 2.4 Human-First原則との関係

Human-First原則はP3とほぼ等価であるが、P3よりも強い言い切りを含む。「AIの決定=存在しない」という表現は、単に「人間の承認が必要」（弱い表現）ではなく、「AIが下したものは制度上そもそも決定として扱われない」（強い表現）という点で、P1（信頼を制度で代替する）とP3を組み合わせた最も先鋭化された表現と位置づけられる。

この整理が正しければ、Human-First原則はP1とP3の合成から導かれる「派生原則」であり、それ自体が独立した第一原理というよりは、MoCKAの中で最も具体的・実務的に運用されている規範という位置づけになる。**この階層づけ（Human-First=P1×P3の合成）が妥当かどうかは、博士確認が必要な最重要論点である。**

### 2.5 各Guarantee（G1〜G10）がどの第一原理から導かれるか

| Guarantee | 由来する第一原理 | 備考 |
|---|---|---|
| G1 存在保証 | P1、P2 | 「制度で縛る」には縛る対象の存在把握が前提。検証可能性の土台でもある |
| G2 不変性・改ざん検知保証 | P2 | 検証可能性の直接的な実装形態 |
| G3 網羅性保証 | P2、P4 | 記録の徹底。失敗を資産にするには漏れなく記録される必要がある |
| G4 実行前安全性保証 | P1 | 「システムで縛る」の最も直接的な発現（GL7） |
| G5 人間最終決定保証 | P3 | 直接対応 |
| G6 暴走・停滞検知保証 | P1、P4 | 逸脱を検知して記録・介入する仕組み |
| G7 品質・妥当性保証 | P1 | 基準による拘束 |
| G8 単一正本保証 | P5、P2 | 矛盾する複数の真実を作らないことは構造の一貫性（P5）と検証可能性（P2）の両方に関わる |
| G9 権限分離保証 | P1、P3 | 一つの主体に全権を持たせないことは、信頼の代替（P1）と人間最終決定の担保（P3）の両方に資する |
| G10 文脈・経験継承保証 | **不明・要確認** | P1〜P5のいずれからも直接には導出しにくい。後述2.6参照 |

### 2.6 将来Guaranteeが増えても崩れない原則になっているか（ストレステスト）

P1〜P5がMoCKAの根源として十分かを検証するため、今回のG1〜G10に含まれない仮想的な新規Guaranteeを2つ想定し、既存原則から導出できるかを試す。

**試行1: 「可用性保証」（システムが一定時間以上停止しないことを保証する）**

P1〜P5のいずれからも直接には導けない。信頼の代替（P1）、検証可能性（P2）、人間最終決定（P3）、失敗の記録（P4）、構造の非破壊的拡張（P5）は、いずれも「止まらないこと」を要求しない。むしろP4（失敗は資産）はある程度の停止・失敗を許容する思想に近く、可用性保証とは方向性が異なる可能性がある。**結論: 可用性保証はP1〜P5からは導出できず、MoCKAが現時点で第一原理として重視していない領域である可能性が高い。これは「意図的に保証しない」のか「単に検討されていない」のかの区別がつかず、要確認。**

**試行2: 「文脈・経験継承保証」（G10、実際に本日のMemory監査で発見された既存の保証主張）**

2.5節で既に「不明」としたが、改めて試行する。P2（検証可能性）は「過去に何が起きたか記録されている」ことを要求するが、これは「記録が存在する」ことであって「記録が必要な時に参照可能な形で継承される」こととは異なる（Ledgerは前者、Memory/Infieldは後者に近い）。P4（失敗は資産）も、資産化された知識が実際に将来のセッションで参照されることまでは保証しない。**結論: G10は既存のP1〜P5からは弱くしか導出できず、「時間・セッションを超えた継続性の保証」という第六の原理（P6候補）が必要である可能性が高い。**

**ストレステストのまとめ:** P1〜P5は「今この瞬間の行為の正しさ・追跡可能性・人間主権」を保証する原理としては一貫しているが、「時間を超えた継続性」（G10）と「稼働し続けること」（可用性、仮想例）という2つの軸には対応していない。これはP1〜P5が不完全である可能性と、MoCKAが意図的にこれらを第一原理の対象外としている可能性の両方があり、**本監査だけでは判別できない。博士確認が必要な最重要の未決事項である。**
