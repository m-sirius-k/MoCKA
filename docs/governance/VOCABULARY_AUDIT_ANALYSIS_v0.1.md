# Vocabulary Audit Analysis v0.1 (Analysis-01)

位置づけ: R01分析指示書v1.0 Analysis-01に基づく。入力資料は`VOCABULARY_AUDIT_EVALUATION_v0.1.md`(v0.3)のみとし、新規調査は行っていない。修正案・実装案・優先順位・ロードマップ・着手順・採否判断は一切含まない。制度上の論点整理を超えて、事実収集結果から読み取れる「構造的特徴」を分析する。他のAnalysis（Cross Reference／CI Failure）とは独立に扱い、それらの結論をここでの分析根拠として用いていない。

## 1. 確認できた事実（Vocabulary Audit Evaluation v0.3より、要約引用）

- 7つの評価軸のうち、設計思想(B)・実装整合性(B)が中間評価である一方、文書整合性(C)・ガバナンス証跡(C)・索引整合性(D)・正本管理(D)・命名ガバナンス(D)の5軸がC以下と評価されている。
- 命名ガバナンス軸で確認された同名異義事象は4系統: Human Gate(2実装、既存監査は4概念と分類)、Registry語根(6系統以上)、Ledger語根(4候補)、Archive語根(3同語異義)。
- `docs/NAMING_CONVENTION.md`という命名規則文書は実在するが、対象は最上位アーキテクチャ名(7件)のみで、本監査が扱うモジュール／概念レベルの語彙は範囲外であることが確認されている。
- 索引整合性の不備として、GL7・TIC・Decision Policy・Guarantee系(4専用文書)・Writer/Checker等、高頻度で使用される制度語が19語辞典に含まれていないことが確認されている。
- 正本管理の不備として、REGISTRY_SCHEMA_v1.0.mdの物理的複製、KN_SERIES_LEDGER・Atlasの実体不在、KN-004とMODULE_CATALOG_v1のスコープ重複未解決が確認されている。
- 各個別実装（Human Gate 2件・capability_registry 3件）は、それぞれ独自の設計文書・契約文書（control_map_v2.md、phase7_b6_human_gate_ruling_v1.md等）を持ち、静的import解析では相互の呼び出し関係（循環・依存）が確認されなかった。
- semantic_dictionary（282MB規模）がevent記録・コミットメッセージのいずれにも説明を伴わずに追加されていたことが確認されている。

## 2. 事実から導かれる分析（構造的特徴）

### 2-1. 評価軸の分布に現れる二極化構造

7軸の評価は明確に二極化している。「個別の実体（コード実装・設計文書）の質」を問う軸（設計思想・実装整合性）はB評価に留まり、「複数の実体を横断して束ねる仕組み（索引・正本・命名規則・文書間参照）」を問う軸（索引整合性・正本管理・命名ガバナンス）はいずれもD評価となっている。これは、個々の成果物単体の作り込みと、複数成果物を制度として統合する仕組みとの間に、評価上明確な落差があることを示す構造的特徴である。

### 2-2. 「同名異義」という単一パターンの反復出現

Human Gate・Registry・Ledger・Archiveという4つの独立した語彙系統すべてで、「同一名称が複数の無関係な概念・実装に割り当てられる」という同一パターンが観測されている。これは個別の語彙ごとに独立に発生した偶発的事象というより、複数の語彙系統に共通する構造的特徴（同一パターンの反復）として現れている。

### 2-3. 「個別には意図的、全体としては未調整」という組み合わせ

命名ガバナンス・実装整合性の両評価から、各実装は個別には設計文書を伴う意図的な設計である一方、複数実装間の名称調整を担う上位の仕組み（ADR・命名規則の拡張等）は確認されていない、という組み合わせが繰り返し現れている。これは「モジュール単位の設計品質」と「モジュール横断の調整機構」が別々の成熟度で存在している構造を示唆する。

### 2-4. 自己申告型の不備記録という文書慣行

文書整合性(C)の根拠として引用された事例（TERM-001のSource未確定、VOCABULARY_CONSTITUTION_v0.1のCatalog禁止事項未確認等）は、いずれも既存文書自身が「未確認」「将来課題」と明記した箇所であり、本分析による新規指摘ではない。これは、MoCKAの制度文書が不備を隠さず自己申告する慣行を持っていることを示す一方、自己申告された不備がその後解消されないまま複数の後続文書に引き継がれている、という進行中の構造的特徴でもある。

### 2-5. ガバナンス証跡の分布における対比

TERM-001・CONCEPT_AUDIT・HUMAN_GATE_*_AUDIT等の正規監査文書群は、CHANGE_START/DONE記録とHuman Approval Gate承認を伴う一貫した記録文化を示す一方、semantic_dictionaryという1件の大規模成果物にはその記録が確認されなかった。全体として記録文化が欠如しているのではなく、特定の成果物カテゴリ（本件では自動抽出的な大規模データ生成物）において記録の慣行が及んでいない、という限定的な構造的特徴として現れている。

## 3. 未確認事項

- 上記の「同名異義パターン」がHuman Gate・Registry・Ledger・Archiveの4系統以外にも存在するかは、Vocabulary Audit Evaluation v0.3が扱った19語＋欠損語候補の範囲でのみ確認されており、リポジトリ全体を悉皆的に確認したものではない。
- 「個別には意図的、全体としては未調整」という組み合わせが、MoCKAの意図的な設計方針（例えば、局所的自律性を優先し中央調整を後回しにする方針）なのか、単に調整が未着手であるだけなのかは、Evaluation v0.3の範囲では判別できない。
- 自己申告型の不備が後続文書に引き継がれるパターンが、TERM-001／VOCABULARY_CONSTITUTION_v0.1以外の文書系列でも一般的に見られる慣行かどうかは未確認。

## 4. 博士判断が必要な事項

- 「モジュール単位の設計品質」と「モジュール横断の調整機構」の成熟度の落差（2-1・2-3）をどう捉えるか（意図した設計上の分業か、埋めるべき空白か）は、事実収集・分析の範囲を超える制度的な位置づけの判断である。
- 自己申告された不備（2-4）を今後どのタイミング・体制で解消するかは、TERM-001改訂等の制度運営に関わる判断であり、本分析の範囲を超える。
- semantic_dictionaryのような記録慣行の及んでいない成果物カテゴリ（2-5）を、今後どう位置づけるか（記録義務の遡及適用を含む）は、記録原則の適用範囲に関わる制度判断である。
