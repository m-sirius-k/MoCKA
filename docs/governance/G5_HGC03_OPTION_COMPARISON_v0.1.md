## 2. 論点の起点となる実測 (Confirmed)

本論点は次の実測から発生している。**以下は事実であり、いずれの選択肢の優位も示さない。**

| # | 実測 | 出典 |
|---|---|---|
| F-1 | TTY Guard の実体は `governance/human_gate_cli.py:36-40` の `_require_tty()` で、`sys.stdin.isatty()` が偽なら `sys.exit(1)` する | コード実測 |
| F-2 | Guard は `approve` / `reject` サブコマンドにのみ適用される | 同上 |
| F-3 | 同ファイル33行が `from phi_os.human_gate import submit, approve, reject, get_state, list_pending` を実行する。CLI は HG-1 バックエンドの front-end である | 同上 |
| F-4 | したがって Guard は HG-1 本体 (`phi_os/human_gate.py`) ではなく **CLI 経路上**にある。同バックエンドを Python から直接 import する経路には TTY 判定が存在しない | F-1 から F-3 の帰結 |
| F-5 | MoCKA 配下の Python コード (`.venv` / `archive` / `node_modules` 除外) で `isatty` を検索した結果、人間性を担保する判定は F-1 の1件のみ (2026-08-06 時点、範囲限定の実測) | 検索実測 |

**すなわち、同一のバックエンド関数に対して、Guard を経由する経路と経由しない経路が併存する。**
この構造がある以上、「HG-1 は Guard を持つか」という問いは、経路を指定しないと一意に答えられない。
HG-C03 はこの一意化の方法を決める裁定である。

## 3. 比較表

### 3.1 制度的利点

| 観点 | A (経路単位) | B (系統単位) |
|---|---|---|
| 判定の一意性 | 経路を指定するため、F-4 のような分岐が判定に現れる | 系統名で一意に指定できるため、判定対象の同定が容易 |
| 既存制度との接続 | `DC_20260805_001` C2-02 (Rule 制定 / Detection / Execution の分離) は実行経路を単位とする構造を持つ。EP-1 から EP-8 の Enforcement Point 体系も経路側の概念である | `DC_20260805_001` Q-3 は Rule 粒度について「監査・承認単位が過剰分割される」ことを理由に定数単位を却下し、Policy Module 単位を Audit / Approval / Change Record の基本単位とした。粒度を粗く保つ判断の先例が存在する |
| 既存観測資産との整合 | F-1 から F-5 は既に経路の性質として記録済み | JARVIS-HGJ04-EV-001 第1章の5系統一覧と粒度が一致し、既存の観測資産をそのまま単位として使える |
| G-5 の問いとの距離 | G-5 は「Human Gate 接続先が5系統並存」という接続先の問題であり、接続先の実体を経路まで降りて特定する | G-5 の記述単位 (5系統) と判定単位が一致する |
| 他 Criterion との関係 | Criterion 5 (不可逆操作境界) も参照位置をコード行で特定する要求を持ち、粒度が揃う | Criterion 1 / 3 / 4 は系統単位の記録先・スキーマを評価対象とするため、Criterion 2 だけが別粒度にならない |

### 3.2 制度的制約

| 観点 | A (経路単位) | B (系統単位) |
|---|---|---|
| 判定の前提条件 | **経路の列挙完全性に依存する**。未列挙の経路が残るかぎり、その系統の判定は完了しない | 系統内に複数経路がある場合、**どの経路の性質を系統の判定値とするかの規則が別途必要**になる (最も弱い経路か、正規経路か)。この規則は現時点で存在しない |
| 判定が取りこぼす方向 | 列挙が不完全なとき、未列挙経路の性質が判定に反映されない。v0.1 4.2.6 はこの場合を UNKNOWN として保留する扱いを `[起案]` している | 系統単位で PASS とした場合、**F-4 のような Guard なし経路の存在が判定値に現れない** |
| 作業量 | 5系統それぞれについて、承認確定に到達しうる経路 (CLI / HTTP route / Python import / MCP tool) を全列挙する必要がある | 系統ごとに1判定。追加の列挙作業は発生しない |
| 表の均一性 | Criterion 2 のセルのみ経路ごとの複数値を持ちうる。他 Criterion のセルと構造が揃わない (PREP CH-3 と同型の非均一性) | 全 Criterion で1セル1値の構造が保たれる |
| 語彙依存 | 未列挙範囲の表現に UNKNOWN 相当の値を要するため、**HG-C01 / HG-C02 の裁定に依存する度合いが高い** | 依存はあるが、未列挙という状態自体が発生しないため度合いは低い |

### 3.3 未確定事項との接触

| 未確定事項 | A (経路単位) | B (系統単位) |
|---|---|---|
| Q-6 Multi Boundary Interceptor Model (Gate 2 の第3優先) | 経路単位の判定は、境界が複数存在することを評価上の前提として扱う。**Q-6 の裁定内容と接触しうる** | 系統単位の判定は境界の複数性を評価に持ち込まないため、接触は小さい |
| G-13 (承認済み Action の判定根拠が EP-3 のみ) | 経路ごとの承認参照の有無が判定に現れるため、**G-13 の観測と同じ面を見る** | 系統単位では EP 単位の差が判定に現れない |
| G-18 (EP-1 / EP-2 / EP-4 / EP-5 の承認非参照が設計意図か未実装か不明) | 経路単位の判定は G-18 の対象範囲に触れるが、**G-18 自体を解消しない** (設計意図か未実装かは判定できない) | 触れない |
| PREP CH-3 (Criterion 間のセル構造の不均一) | 発生する | 発生しない |

**注意:** 上表は接触の有無の記述であり、接触することが不利、接触しないことが有利という評価ではない。
`DC_20260805_001` は Unknown 23件を解消0のまま保持する形で Gate 1 を通過させている。

### 3.4 後続工程への影響

| 工程 | A (経路単位) | B (系統単位) |
|---|---|---|
| 証拠収集 (比較工程) | 経路の全列挙が必要。**系統単位で収集した証拠は流用できない** | 既存の JARVIS-HGJ04-EV-001 の観測を起点にできる |
| 比較表 (5x5) | Criterion 2 の5セルが経路ごとの内訳を持つ | 5セルとも単一値 |
| G-5 Decision Criteria Report | 経路単位の記述になるため、正典候補の記述も経路への言及を伴いうる | 系統名のみで記述できる |
| 正典選定 (Gate 2 以降、本工程の対象外) | 「どの系統を正典とするか」に加えて「その系統のどの経路を正規経路とするか」が論点として派生しうる | 系統の選択に閉じる |
| 再作業リスク | 先に B で収集した後 A へ変更した場合、**証拠収集のやり直しが発生する** (PREP 4.3) | 先に A で収集した後 B へ変更した場合、収集済み証拠は上位の系統単位へ集約可能。ただし集約規則 (3.2 の判定前提条件) が別途必要 |

### 3.5 判定結果が誤りうる方向 (対称記述)

| 選択肢 | 誤りの型 | 内容 |
|---|---|---|
| A | 保留過剰 | 経路列挙が完了しないかぎり判定が UNKNOWN に留まり、実際には要件を満たす系統も未判定のまま残りうる |
| B | 見落とし | 系統内に Guard を持たない経路があっても、系統単位の判定値には現れないため、要件を満たさない経路が可視化されないまま残りうる |

   3.2 の語彙依存の記述は依存関係の事実であって、HG-C01 の選択に影響を与える意図を持たない
