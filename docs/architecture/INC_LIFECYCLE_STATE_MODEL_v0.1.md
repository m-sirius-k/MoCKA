## 2. 状態モデル(最小)

### 2.1 状態

| 状態 | 定義 | この状態で保証されること |
|------|------|--------------------------|
| `DETECTED` | リスク検知によりINCが生成された直後 | 検知理由・イベント参照が存在する。再発防止情報は**存在しない** |
| `ANALYZED` | 原因分析が完了し、再発防止情報が確定した | 再発防止情報が所定の位置に存在する(条項 S-3) |
| `APPROVED` | 公開してよいと人間が判断した | 公開可否の判断が行われた |
| `PUBLISHED` | GPT_RESTRICTIONS.md へ反映済み | 公開ファイルの内容と一致する |
| `CLOSED` | 当該INCの取り扱いが終結した | 以降の状態変更を行わない |
| `REJECTED` | 公開しないと人間が判断した | 公開対象から恒久的に除外される |

v0.1では上記6状態に限定する。`IMPLEMENTING` `VERIFIED` 等の実装追跡状態は、
本パイプライン(検知から公開まで)の外側であるため v0.1 に含めない。

### 2.2 遷移

```
   [検知]
      |
      v
  DETECTED
      |  T1: 分析完了            (実行主体: 機械可)
      v
  ANALYZED
      |  T2: 公開可の判断        (実行主体: 人間のみ)
      |  T3: 公開不可の判断      (実行主体: 人間のみ)
      |                                |
      v                                v
  APPROVED                         REJECTED
      |  T4: 公開処理の実行      (実行主体: 機械可)     |
      v                                                |
  PUBLISHED                                            |
      |  T5: 終結                (実行主体: 人間のみ)   |
      v                                                v
   CLOSED <-------------------------------------------- 
```

### 2.3 遷移条件と実行主体

| 遷移 | 事前条件 | 実行主体 | 根拠 |
|------|----------|----------|------|
| T1 `DETECTED -> ANALYZED` | 再発防止情報が所定の位置に生成されていること | 機械可 | 分析の自動生成は現行の5W1Hエンジンが担う |
| T2 `ANALYZED -> APPROVED` | 状態が `ANALYZED` であること | **人間のみ** | DC_20260731_003 の設計前提 |
| T3 `ANALYZED -> REJECTED` | 状態が `ANALYZED` であること | **人間のみ** | 同上 |
| T4 `APPROVED -> PUBLISHED` | 状態が `APPROVED` であること | 機械可 | 承認済みのものを反映する作業であり判断を含まない |
| T5 `PUBLISHED -> CLOSED` / `REJECTED -> CLOSED` | - | **人間のみ** | 終結は判断である |

### 2.4 自動承認の禁止(DC_20260731_003 の設計前提)

**条項 S-1(必須)**: T2 および T3 を機械が実行してはならない。

D-1 は承認ゲートが存在しないという欠陥である。その是正が"機械が承認を出せる"設計に
なった場合、公開可否の判断者が不在であるという本質は変わらない。したがって
遷移条件の明文化(2.3節)と、遷移を実行できる主体の限定(本条項)は別々の設計項目として扱う。

`ANALYZED` への遷移(T1)が自動であることは許容する。分析の生成と、その分析を
公開してよいという判断は別の行為であるためである。

## 3. D-1/D-2/D-3 との対応

確定済み定義(INC_PIPELINE_FAILURE_ANALYSIS_v0.1.md、Confirmed)に対応付ける。
外部提示の指示書が用いていた別定義(D-2=状態の記録が散在 / D-3=遷移履歴が追跡できない)は
DC_20260731_003 で採らないことが確定しているため、以下では用いない。

| 欠陥 | 確定済み定義 | 状態モデル上の不備としての表現 | 本モデルでの解決 |
|------|--------------|--------------------------------|------------------|
| D-1 | 承認状態確認分岐の不存在。`tools/mocka_restrictions.py:12-19` が `## 承認` 欄を参照しない | `PUBLISHED` への遷移(T4)に事前条件が存在しない。任意の状態から公開されうる | T4 の事前条件を `APPROVED` に限定する(条項 S-2) |
| D-2 | 生成順序逆転。`risk_engine.py:155`(公開)が `158-159`(分析)より先 | `DETECTED` のまま公開処理が起動する。`ANALYZED` を経ない | 状態遷移の順序を強制する。`DETECTED` からは `PUBLISHED` へ到達できない |
| D-3 | 抽出範囲不足。`restrictions.py:16-17` が `## 再発防止` 直後から次の `##` までに限定 | `ANALYZED` が何を保証するかが定義されていない。生産者と消費者で再発防止情報の位置が食い違う | `ANALYZED` の成果物契約を定義する(条項 S-3) |

### 3.1 条項

**条項 S-2(必須)**: `PUBLISHED` への遷移は、状態が `APPROVED` である場合のみ許可する。

**条項 S-3(必須)**: `ANALYZED` は、再発防止情報が**単一の所定位置**に存在することを保証する。
生産者(分析を書く側)と消費者(公開へ転記する側)は同一の位置を参照する。

条項 S-3 が D-3 の本体である。現行は生産者が `## 5W1H分析` 配下へ書き、
消費者が `## 再発防止` 配下を読むという不一致がある。所定位置を
どちらに寄せるか(生産者側を変えるか消費者側を変えるか)は第6節の未確定事項とする。

**条項 S-4(必須)**: 状態遷移は記録される。遷移の実行主体・時刻・遷移前後の状態を残す。

### 3.2 D-2単独是正が無効である理由の再掲

DC_20260731_003 の根拠にあたる事実として記録する。順序のみを入れ替えても、
条項 S-3 が無い限り最終出力は変わらない。`tools/mocka_5w1h.py:135-136` は末尾へ
append するのみで `## 再発防止` 欄を書き換えないため、`restrictions.py:16-17` の
抽出結果は不変である(4通りの是正組合せ表、INC_PIPELINE_DEFECT_DEPENDENCY_v0.1.md 4.2節)。

したがって D-2 の解決は"順序の入替"ではなく"状態遷移の順序強制 + 条項 S-3"である。

## 4. 状態の保持場所

現行は状態が存在しない。`## 承認：` 欄に散文が書かれるのみで、読まれることがない。

保持場所の候補と性質を示す。選定は行わない(第6節)。

| 候補 | 性質 | 懸念 |
|------|------|------|
| (a) INCファイル内の構造化ヘッダ | 現行構造からの変更が最小。人間が直接編集できる | 3役未分化の問題が残る。書式の揺れが判定に影響する(既存2件で `## 承認` の書式が不一致) |
| (b) 別ファイル(状態レコード) | 検知記録と状態を分離できる | INCファイルとの整合維持が必要 |
| (c) events.db / 既存イベントストア | 遷移記録(条項 S-4)と同じ場所に置ける | data/events.csv 系との関係整理が必要 |
| (d) Decision Ledger | 承認遷移(T2/T3)は裁定であり親和性がある | 全遷移を置くには粒度が細かすぎる可能性 |

現行の書式不一致(実測):

- INC-20260401-001: `## 承認：Claude Sonnet 4.6 / 2026-04-01`(同一行)
- INC-20260401-002: `## 承認：` の次行に `自動生成 / 要Claude確認`(別行)
- INCIDENT_TEMPLATE.md: `## 承認：` のみ(空)

候補(a)を採る場合、この書式差を判定がどう扱うかを定義する必要がある
(回帰試験 R-03 が該当)。

## 5. 既存INCの移行

現存する `INC-*.md` は2件。移行時の初期状態の割り当てを示す。

| ファイル | 現状 | 初期状態の候補 | 根拠 |
|----------|------|----------------|------|
| INC-20260401-001 | 再発防止3行あり、承認欄に人間名 | `PUBLISHED` | 分析済みかつ公開済み。GPT_RESTRICTIONS.md に反映されている |
| INC-20260401-002 | 再発防止は `（要分析）`、5W1H分析あり、承認欄は `自動生成 / 要Claude確認` | `DETECTED` または `ANALYZED` | 5W1Hは付与済みだが `## 再発防止` 欄は未分析のまま。条項 S-3 の所定位置をどちらに定めるかで結論が変わる |

INC-20260401-002 の初期状態が条項 S-3 の決定に依存する点は、移行が設計判断と
不可分であることを示す。なお同INC由来の `（要分析）` は現に
GPT_RESTRICTIONS.md:29-31 へ公開済みであり、origin/main へ到達している。

対象外: `INCIDENT_IMPORT_APP_SIDE_EFFECT.md` / `CHANGE_PLAN_IMPORT_APP_SIDE_EFFECT_v1.md` は
`INC-*` のglobに合致せず現行でも抽出対象外である。`INCIDENT_TEMPLATE.md` も同様。
